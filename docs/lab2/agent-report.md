# Отчёт о работе с ИИ-агентом

Агент — Claude Code (модель Claude Opus 5.5) в терминале, с доступом к репозиторию, оболочке и Docker. Работа велась в одной сессии 9 ноября 2026 года в ветке `lab2`. Агент сам запускал команды, писал файлы, собирал проект и проверял результат. Решения по стеку и формату сдачи принимала команда, и они зафиксированы ниже вместе с исходными формулировками.

## 1. Постановка задачи

Первый запрос был коротким: задание ЛР 2 лежит в папке курса, ЛР 1 готова, вторую работу нужно сделать в том же репозитории. Агент прочитал PDF с заданием (`pikpo_lab2_2026.pdf`) и отчёт ЛР 1, выписал объём работ для команды (три диаграммы активности, wireframe-ы, 5 ADR) и требования, на которые ADR должны ссылаться. Перед тем как писать код, он задал два вопроса.

> На каком стеке делаем исполняемый прототип? Варианты: React + Vite с mock-API (рекомендуется), React + NestJS + SQLite, Angular с mock-API.

> В каком виде сдаём архитектурный документ и отчёт? Варианты: Markdown в репозитории и .docx с титульным листом (рекомендуется) или только Markdown.

Команда выбрала **React + NestJS + PostgreSQL**, то есть вариант, которого агент не предлагал, и **только Markdown**. Агент рекомендовал mock-API, потому что так быстрее. Команда предпочла настоящий сервер, чтобы прототип отражал архитектуру, а не изображал её. Дальше вся работа шла под этот выбор (ADR-001, ADR-002).

## 2. Ход работы

**Каркас проекта.** Проекты агент создавал официальными генераторами (`@nestjs/cli new`, `create vite`, `prisma init`). Сам он объяснил это так: установленные версии (NestJS 12, Vite 8, Prisma 7, TypeScript 7) новее того, что он знает, и конфиги по памяти скорее окажутся устаревшими. Почти сразу появилось две проблемы. Установка зависимостей Nest упала с ошибкой `Cannot read properties of null (reading 'edgesOut')`. Агент нашёл в логе, что это ошибка разрешения peer-зависимостей в npm 10, и поставил пакеты через npm 11, поэтому в `package.json` указано `"npm": ">=11"`. Вторая проблема: генераторы положили в проект служебные файлы для ИИ-агентов (`.claude/skills`, `.agents`, `.windsurf`, `AGENTS.md`, `skills-lock.json`). Агент прочитал справку Prisma 7 из этих файлов как документацию, а затем удалил их из репозитория.

**Сервер.** Сначала агент написал Prisma-схему, по которой потом нарисована ER-диаграмма. Затем — доменное ядро из чистых функций и модули Nest вокруг него. Задача в формулировке агента звучала так: «расчёты, для которых в ЛР 1 даны числа, вынести в функции без зависимостей и проверить тестами на этих же числах». Получилось 23 юнит-теста: норма 2345 ккал и БЖУ 176/78/235 г (FR-02), 21 блюдо за 7 дней и отклонение дня ≤ 10 % (FR-05), не больше 2 повторов в неделю (FR-06), 700 г → 2 упаковки (FR-12), «Магнит» с экономией 30 ₽ (FR-13), пара сетей с экономией 250 ₽ и отсутствие предложения при 100 ₽ (FR-14), превышение бюджета на 800 ₽ (FR-15). Ещё 6 e2e-тестов проходят весь сценарий через HTTP на живой базе, от регистрации до ИИ-анализа.

**Wireframe-ы и клиент.** Задание требует согласовать UI до программирования. Поэтому клиент агент начал писать только после того, как нарисовал десять wireframe-ов в PlantUML Salt и проверил их рендер. Клиентский код повторяет экраны и переходы с wireframe-ов.

**Документация.** Диаграммы агент писал как PlantUML-исходники и рендерил в PNG через Docker-образ `plantuml/plantuml`. Каждую картинку он открывал и проверял глазами. ADR написаны по шаблону из задания, а раздел «Роль агента» в каждом описывает, что происходило на самом деле.

## 3. Проверка и найденные ошибки

Код агент проверял не только тестами, но и в браузере. В WSL не хватало системных библиотек для Chrome, поэтому он запустил headless Chrome в контейнере `ghcr.io/puppeteer/puppeteer` и прошёл сценарий скриптом: регистрация с ошибкой валидации, профиль, рацион, замена блюда, рецепт, список покупок, корзины, ИИ-анализ, семья. Затем — те же экраны на ширине 360 px с замером `scrollWidth`. Скриншоты лежат в [screenshots](screenshots/). Проверки нашли ошибки, которые тесты пропустили:

| Что нашли | Причина | Исправление |
|---|---|---|
| Страница профиля нового пользователя падала | сервер отвечал на `GET /profile` пустым телом, клиент превращал его в `{}` | пустое тело теперь означает `null` |
| Окно замены блюда закрывалось сразу после открытия | в StrictMode React cleanup эффекта вызывал `dialog.close()`, а событие `close` вызывало `onClose` | cleanup убран, повторный `showModal` защищён проверкой `dialog.open` |
| Порции 1,75 показывались как «1,8» | общий формат чисел с одним знаком | для порций отдельный формат с двумя знаками |
| В списке покупок «7,3 шт» яиц | штучные продукты не округлялись | штуки округляются вверх, добавлен тест |
| На 360 px список покупок шире экрана (427 px) | колонки таблицы и шапка не ужимались | мобильные стили, повторный замер — 360 px |
| Раскрытый состав одной корзины растягивал соседние карточки | выравнивание сетки по умолчанию | `align-items: start` |

Ещё две ошибки агент нашёл, когда проверял данные через API. Первая версия заглушки ИИ писала «жиры в пределах нормы» при отклонении −47 %, а белок занижала, потому что учитывала дни с блюдом без данных о БЖУ. Вторая: недельная корзина одного человека стоила около 9 300 ₽ при бюджете 3 500 ₽. Агент разложил её по позициям и показал, что дело в округлении до упаковок, после чего поменял тестовые фасовки (подробности в ADR-004 и ADR-005). В диаграммах агент нашёл две неточности: в wireframe профиля норма 2345 ккал стояла рядом с целью «сохранить вес», хотя посчитана для «снизить», а на альтернативной диаграмме активности шаг пользователя попал на дорожку системы.

## 4. Где агента пришлось ограничить

Сбросить базу командой `prisma migrate reset` агент не смог: Prisma 7 блокирует её для ИИ-агентов, если пользователь явно не согласился. Обходить запрет агент не стал и вместо этого сделал сид идемпотентным: каталог создаётся один раз, а цены обновляются при каждом запуске. Получилась ближе к реальности модель ежедневного обновления цен (NFR-03).

Перед удалением сгенерированных файлов агент проверил их содержимое. Ветку другого участника команды, где лежали собранные архивы, он не трогал. Чтобы история не раздувалась, в корневой `.gitignore` добавлены `*.zip`, `output/`, `dist/` и `node_modules/`.

## 5. Выводы

Сильнее всего агент помог там, где нужно было много связанной рутины: схема данных, модули сервера, клиентские экраны, диаграммы, и всё это согласовано между собой. Структурная схема, ER-диаграмма, контракты API и код описывают одну и ту же систему, потому что агент писал их подряд и сверял друг с другом. Полезно было и то, что он не доверял собственному коду: самые заметные ошибки (падение профиля, закрывающееся окно, неверный текст анализа) нашлись только потому, что агент открывал результат в браузере и смотрел на числа.

У агента есть и ограничения. Версии библиотек ушли дальше его знаний, и ему приходилось читать типы и справку прямо из `node_modules`. Тестовые цены и рецепты он сгенерировал сам, поэтому это правдоподобные, но не рыночные данные. Выбор стека и формата сдачи остался за командой, и в главном вопросе, о бэкенде, команда не согласилась с рекомендацией агента.
