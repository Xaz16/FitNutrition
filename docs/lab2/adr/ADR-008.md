# ADR-008: Python для серверной логики

## Статус

Принято. Уточнение архитектуры действующего прототипа от 26.10.2026.

## Контекст

FR-02 требует сохранения параметров и расчёта нормы, FR-05 - составления меню, FR-07 - замены блюда с пересчётом. NFR-01 задаёт bcrypt cost 12 и ограничение попыток входа; NFR-02 задаёт p95 генерации до 5 с на условиях ЛР1. Python объединяет эти правила на сервере: domain.py выполняет расчёты, profiles.py проверяет профиль, replacements.py обрабатывает замены. Выбор языка сам по себе не подтверждает выполнение NFR-02: соответствующие нагрузочные проверки не проводились. HTTPS из NFR-01 пока не реализован.

## Проблема

Нужно сохранить понятный и воспроизводимый прототип без сборки фронтенда и без повторной реализации готовых расчётов на другом языке.

## Рассмотренные альтернативы

Node.js позволил бы использовать JavaScript на обеих сторонах, но потребовал бы переноса расчётов и слоя БД. Python с FastAPI дал бы декларативные контракты, но добавил бы зависимости и настройку приложения. Переписывание на Java или C# не решает задачу текущей итерации.

## Принятое решение

Продолжать использовать Python 3.10+ и стандартный ThreadingHTTPServer для локальной демонстрации. Оставить один серверный процесс и модули по ответственности. Внешняя зависимость приложения нужна для bcrypt; инструменты построения отчёта не входят в рабочий стек.

## Последствия

Сохраняется простой запуск и единое место вычислений. Валидация маршрутов написана вручную, интерактивная спецификация OpenAPI отсутствует. http.server не является выбранным сервером публичного продукта. Перед публикацией нужны сервер приложений, HTTPS и пересмотр эксплуатации.

## Роль агента

Агент описал существующее разбиение модулей и альтернативы без изменения стека. Заявление о сравнительной скорости языков не делается, соответствующих измерений нет.
