# Fit Nutrition Supply

Запускаемый прототип ЛР2. Основная ЦА — взрослые с интересом к снижению веса. Пилотный город — Ижевск. Цены пяти сетей, пищевая ценность и рецепты — учебные данные, а не подключённые каталоги магазинов.

## Быстрый запуск Windows

Нужен Python 3.12 или новее. В PowerShell из папки `prototype`:

```powershell
powershell -ExecutionPolicy Bypass -File .\Start.ps1
```

Скрипт создаёт локальную `.venv`, устанавливает единственную зависимость bcrypt и открывает браузер. Интернет нужен только при первой установке зависимости. Приложение открывается по адресу http://127.0.0.1:8765. Остановка — Ctrl+C в окне сервера.

Если окружение уже создано, но установка прервалась, выполните `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` и повторите запуск.

## Запуск вручную

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py --open
```

Linux/macOS: `python3 -m venv .venv`, `.venv/bin/python -m pip install -r requirements.txt`, `.venv/bin/python server.py --open`.

## Демонстрация

1. Откройте демоверсию либо зарегистрируйте тестовый аккаунт. Демо создаёт отдельную учётную запись без пароля.
2. Оставьте параметры примера и составьте меню на 7 дней. Цель по умолчанию — снизить вес.
3. Откройте рецепт, выберите замену и подтвердите. Изменится одна позиция, список и корзины пересчитаются.
4. В списке введите запас любого продукта и отметьте купленную позицию.
5. Откройте корзины. Посмотрите полную сумму, фасовки, остатки и бюджет. Неполная сеть не победит полную.
6. Нажмите «Показать сбой источника»: появится ошибка, прежние предложения и сумма останутся.
7. Перезагрузите страницу: план сохранён. Чтобы показать ошибку валидации, в настройках задайте 6 дней; чтобы показать нехватку рецептов — максимум 5 минут готовки.

## Хранение и ограничения

SQLite создаётся автоматически в `data/fitnutrition.sqlite3`. Каталог загружается один раз. Эта папка и `.venv` исключены из Git. При переносе на другой компьютер база не переносится автоматически: созданные аккаунты и планы остаются на запущенном сервере. Доступ с других устройств и HTTPS требуют отдельного развёртывания; текущий сервер намеренно слушает только loopback.

Семейные профили, реальные цены, ручное сопоставление товаров, корзина из двух сетей, ИИ-анализ, шаблоны, фактические расходы, оформление и оплата пока не реализованы. БЖУ показывается фактическое по учебным ингредиентам, точное попадание в целевое соотношение не гарантируется. Полная матрица требований — в отчёте ЛР2.

## Проверки

Из корня репозитория, используя Python окружения прототипа:

```powershell
prototype\.venv\Scripts\python.exe -m unittest discover -s prototype/tests -v
```

Браузерный тест дополнительно требует Node.js, Playwright и установленный Google Chrome. При доступном npm-пакете playwright: `node prototype/tests/browser.cjs`. Он использует уже запущенный сервер; нестандартный адрес передаётся переменной TEST_URL. Для пакетного размещения Playwright можно задать PLAYWRIGHT_MODULE абсолютным путём. Артефакты проверки сохраняются только в tmp/lab2/browser-qa.
