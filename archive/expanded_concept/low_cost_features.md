# Функции при небольших затратах

## Принцип реализации

Большая часть полезных функций выполняется обычным кодом в браузере. Первую версию можно разместить как статическое веб-приложение с локальным хранилищем. Выбор технологии и хостинга делается на этапе прототипа; стоимость тарифа здесь не предполагается. Отдельный сервер, аккаунты и платные вызовы модели не обязательны для основного сценария. Бесплатность для пользователя не означает отсутствие затрат на разработку, проверку рецептов и поддержку.

Оценки сложности ниже — предварительная инженерная оценка, а не измеренное время разработки. Низкая означает, что функция использует уже имеющиеся данные и простое преобразование; средняя — что понадобятся дополнительные правила, алгоритм или проверка данных.

Не каждую функцию нужно писать отдельно: изменение порций уже даёт пересчёт ингредиентов, БЖУ, упаковок и стоимости. Замена блюда использует те же расчёты. История оценок одновременно служит основой аналитики и объяснений.

## Как работает подбор без постоянных запросов к ИИ

1. Отфильтровать рецепты с запрещёнными ингредиентами и неполным составом.
2. Применить лимит времени и другие явные настройки.
3. Ранжировать допустимые блюда по предпочтениям, повторениям, использованию запасов и оценочной закупке.
4. Заполнить выбранные даты, сохранив закреплённые блюда.
5. Пересчитать продукты и стоимость; показать нехватку данных и превышение бюджета.

Это подбор по правилам, а не гарантия глобального оптимума и точного достижения всех пищевых целей. При конфликте ограничений сервис сообщает о нём и предлагает изменить мягкие настройки; запрет ингредиента автоматически не снимается.

Встроенные объяснения формируются из результатов правил. Дополнительный вариант — кнопка копирования структурированного запроса для выбранного пользователем ИИ. Текст собирается локально; передача происходит только по действию пользователя. Веб-приложение не хранит секретный ключ провайдера. Полноценный агент через API остаётся будущим расширением и отдельной статьёй затрат.

## Границы экономии ресурсов

Начинаем с небольшого структурированного каталога знакомых блюд. Состав и пищевая ценность должны иметь источник; данные не генерируются и не выдаются за проверенные без проверки. Цены вводятся или импортируются пакетно. Не обновляем все товары при каждом клике: используем сохранённые предложения с меткой времени.

Данные остаются в конкретном профиле браузера. Между устройствами перенос возможен через резервную копию. Очистка браузера может удалить данные, поэтому предлагаем экспорт. Отсутствие аккаунтов исключает автоматическую совместную синхронизацию в первой версии. Работа без сети после перезапуска потребует отдельного кэширования приложения; одно локальное хранилище её не гарантирует.

## Расширения с заметными затратами

Автоматический сбор актуальных предложений разных сетей, облачная синхронизация семьи, распознавание чеков и продуктов по фото, интеграции корзин и собственный агент с постоянными API-вызовами. Их включаем после проверки источников и пользы. Партнёрские скидки добавляются после появления реальных условий; без договора допустимы обычные ссылки на источник без заявления о партнёрстве.

## Ближайшая последовательность

Сначала закрытый каталог и единая цепочка «меню — продукты — упаковки — стоимость». Затем локальное сохранение, перенос и замена блюд, запасы, оценки и аналитика. После этого пакетный импорт цен, сравнение магазинов, резервные копии и печать. Автоматические интеграции проверяются отдельно. Все функции этой базы бесплатны для пользователя.
